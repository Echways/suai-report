# Команда `suai`

[← К оглавлению](../README.md#документация)

Команда появляется после [установки](install.md). Она создаёт отчёты
и собирает их теми же настройками, что и VS Code.

| Команда | Что делает |
| --- | --- |
| `suai new ПАПКА` | новый отчёт в папке |
| `suai next` | следующий отчёт рядом с текущим: `lab-3` → `../lab-4` |
| `suai build [ПАПКА]` | собрать PDF |
| `suai watch [ПАПКА]` | пересобирать при каждом сохранении |
| `suai open [ПАПКА]` | собрать и открыть PDF |
| `suai clean [ПАПКА]` | удалить `build/` и готовый PDF |
| `suai update` | обновить `.vscode/` в текущем отчёте |
| `suai install` | поставить `suai-report.sty` и саму команду |
| `suai uninstall` | убрать установленное |

`ПАПКА` у `build`, `watch`, `open` и `clean` не обязательна: без неё берётся
текущая папка, в ней должен лежать `main.tex`. Краткая справка — `suai -h`.

## Новый отчёт

```bash
suai new ../lab-1 --title "Чтение из файла на C++"
```

В папке появляется всё нужное для работы:

```text
lab-1/
├── main.tex       заготовка с заполненным титулом
├── images/        сюда кладутся рисунки
├── .vscode/       сборка, подсказки и сниппеты для VS Code
└── .gitignore     build/
```

После этого открывается VS Code с `main.tex` — если в системе есть команда
`code`.

| Ключ | Что делает |
| --- | --- |
| `--title "…"` | название работы на титуле. Без него в `main.tex` остаётся «Название работы» |
| `--no-open` | не открывать VS Code |

Знаки `% # & _ ^` в названии экранируются сами, `$…$` остаётся формулой,
название со знаком `=` берётся в фигурные скобки: `--title "Расчёт y = kx"`
даёт `title = {Расчёт y = kx}`.

Команда откажется работать, если в папке уже есть `main.tex` или если это
папка самого шаблона.

## Откуда берётся титул

Блок `\suaisetup{…}` нового отчёта копируется из готового, чтобы не вводить
кафедру, преподавателя и группу заново:

1. `suai next` берёт его из текущего отчёта;
2. `suai new` — из соседней папки с `main.tex`, которая менялась последней;
3. если соседних отчётов нет — из [demo/main.tex](../demo/main.tex).

Три ключа при этом ставятся заново:

| Ключ | Значение |
| --- | --- |
| `number` | число в конце имени папки: `lab-4` → 4, `lab-04` → 4; имя без числа — пустой номер |
| `title` | из `--title` или «Название работы» |
| `date` | `today` |

Из какого файла взят титул, команда пишет после создания отчёта. Все ключи
описаны на странице [«Титульный лист»](title.md).

## Следующий отчёт

```bash
cd lab-4
suai next --title "Запись в файл"     # создаст ../lab-5
```

Имя текущей папки должно заканчиваться числом. Ведущие нули сохраняются:
после `lab-09` идёт `lab-10`. Ключи те же, что у `suai new`.

## Сборка

```bash
suai build        # один раз
suai watch        # пересобирать при каждом сохранении, остановка — Ctrl+C
suai open         # собрать и открыть PDF
suai clean        # удалить build/ и готовый PDF
```

Служебные файлы сборки лежат в `build/`. Готовый PDF копируется рядом
с `main.tex` и называется по двум папкам:

```text
Databases/lab-3/main.tex  →  Databases/lab-3/Databases-lab-3.pdf
```

Этот файл и сдаётся. `suai build` запускает `latexmk` с теми же аргументами,
что записаны в `.vscode/settings.json` отчёта, поэтому PDF из терминала
и из VS Code получается одинаковым. `suai-report.sty` при сборке командой
берётся из папки шаблона, даже если `suai install` не выполнялся.

## Обновление настроек отчёта

```bash
cd lab-3
suai update
```

Переписывает изменившиеся файлы в `.vscode/` свежими из шаблона и, если
`suai-report.sty` установлен копией, обновляет её. Свои правки в `.vscode/`
отчёта при этом теряются: менять настройки стоит в `src/vscode/` шаблона.
