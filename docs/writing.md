## Каркас документа

```latex
\documentclass[a4paper,14pt]{extarticle}
\usepackage{suai-report}

\suaisetup{
  % данные титульного листа
}

\begin{document}

\maketitle
\suaitoc

\suaiintro
…
\section{Ход работы}
…
\suaiconclusion
…
\suaisources
…
\end{document}
```

Кегль основного текста задаёт класс: `14pt` у `extarticle`. Собирается
отчёт только XeLaTeX. Ключи `\suaisetup` описаны на странице
[«Титульный лист»](title.md).

## Правило блоков

**Блочная команда читает строки под собой до пустой строки.** Каждая
строка становится пунктом перечисления, строкой таблицы, пояснением
к формуле или источником. Блочные команды: `\suaitasks`, `\suailist`,
`\suaienum`, `\suainum`, `\suaitable`, `\suaieq`, `\suaisources`.

```latex
Основные элементы интерфейса:
\suailist
панель файлов слева
редактор в центре

Следующий абзац начинается после пустой строки.
```

Подробности:

- **Один пункт — одна строка исходника.** Длинный пункт на две строки
  не разбивается: вторая строка стала бы следующим пунктом. В VS Code
  длинные строки переносятся на экране сами.
- **Блок кончается** на пустой строке, в конце файла и на строке, которая
  начинается с `\suai…`, `\section`, `\subsection`, `\subsubsection`,
  `\paragraph`, `\begin`, `\end`, `\par`, `\clearpage`, `\newpage`,
  `\maketitle` или `\printbibliography`. Перед такой строкой пустая строка
  не обязательна.
- Строка, которая начинается с любой другой команды (`\texttt{…}`,
  `\bar{x}`), — обычная строка блока.
- **Текст сразу под блоком попадёт в блок.** Перед следующим абзацем
  нужна пустая строка.
- **Комментарий `%`** относится только к своей строке. Строка из одного
  комментария пропускается и блок не обрывает. `\%` и `%` внутри фигурных
  скобок (`\url{…a%20b}`) остаются знаком процента.
- Пробелы в начале и конце строки отбрасываются, поэтому ячейки таблицы
  можно выравнивать в исходнике.

`\suaicode` устроена иначе: код под ней пишется **с отступом** и кончается
на первой строке без отступа — см. [«Листинги»](#листинги).

## Структура отчёта

| Команда | Что даёт |
| --- | --- |
| `\suaitoc` | «СОДЕРЖАНИЕ» с новой страницы |
| `\suaiintro` | «ВВЕДЕНИЕ» |
| `\suaiconclusion` | «ЗАКЛЮЧЕНИЕ» |
| `\suaisection{Название}` | любой другой структурный элемент без номера |
| `\section`, `\subsection`, `\subsubsection` | нумерованные раздел, подраздел, пункт |
| `\suaisources` | [«СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ»](#список-источников) |
| `\suaiapp{Название}` | [приложение](#приложения) |

Структурные элементы без номера печатаются прописными по центру, начинаются
с новой страницы и попадают в содержание. Название пишется обычными буквами:

```latex
\suaisection{Перечень сокращений и обозначений}

В настоящем отчёте применяются следующие сокращения и обозначения:

ОС — операционная система;
```

Заголовки `\section`, `\subsection` и `\subsubsection` набираются
полужирным с абзацного отступа, точка в конце не ставится. Все три уровня
нумеруются и попадают в содержание. Каждый `\section` начинается с новой
страницы; как это отключить, сказано
в [настройке под методичку](customization.md).

```latex
\section{Ход работы}

\subsection{Алгоритм}
```

## Перечисления

| Команда | Вид пунктов |
| --- | --- |
| `\suailist` | – через тире |
| `\suaienum` | а), б), в) |
| `\suainum` | 1), 2), 3) |
| `\suaitasks` | вводная фраза и пункты а), б), в) |

```latex
К программе предъявляются требования:
\suaienum
имя файла передаётся аргументом командной строки
дробная часть числа отделяется точкой
при ошибке программа завершается с ненулевым кодом
```

> а) имя файла передаётся аргументом командной строки;\
> б) дробная часть числа отделяется точкой;\
> в) при ошибке программа завершается с ненулевым кодом.

Пункт начинается с абзацного отступа, его следующие строки идут от левого
поля, как у обычного абзаца. Буквы ё, з, й, о, ч, ъ, ы, ь в нумерации
пропускаются: после «ж)» идёт «и)».

### Пунктуация

После каждого пункта ставится «;», после последнего — «.». Поэтому знаки
в конце строк можно не писать.

- Свои `;`, `.` и `,` в конце строки заменяются на нужный знак.
- `?`, `!` и `:` в конце остаются как есть.
- Точка сокращения сохраняется, «;» ставится после неё: «и т. д.;»,
  «2026 г.;». Так распознаются `и т. д.`, `и т. п.`, `и др.`, `и пр.`, `г.`,
  `гг.`, `вв.`, `руб.`, `коп.`, `тыс.`, `шт.`, `экз.`, `стр.`
- Со звёздочкой пунктуация не трогается: `\suailist*`, `\suaienum*`,
  `\suainum*`, `\suaitasks*`.

### Задачи работы

`\suaitasks` печатает вводную фразу «Для достижения поставленной цели
необходимо решить следующие задачи:» и перечисление а), б), в):

```latex
Цель работы — освоить чтение данных из текстового файла.

\suaitasks
изучить классы файловых потоков стандартной библиотеки
разработать алгоритм чтения чисел
написать и проверить программу
```

Свою фразу задаёт необязательный аргумент, пустой аргумент убирает её
совсем:

```latex
\suaitasks[В работе решаются задачи:]
…

\suaitasks[]
…
```

### Вложенные перечисления

Блочные команды дают один уровень. Двухуровневое перечисление пишется
окружением `gostenum`: первый уровень — буквы, второй — цифры. Пунктуация
в окружении ставится вручную.

```latex
\begin{gostenum}
  \item числа в файле закончились:
  \begin{gostenum}
    \item установлены оба признака;
    \item это штатное завершение;
  \end{gostenum}
  \item в файле встретилось не число.
\end{gostenum}
```

> а) числа в файле закончились:\
> &emsp;1) установлены оба признака;\
> &emsp;2) это штатное завершение;\
> б) в файле встретилось не число.

Обычные `itemize` (тире на обоих уровнях) и `enumerate` оформлены так же,
как блочные команды. У вложенного `enumerate` порядок обратный: первый
уровень — цифры 1), 2), второй — буквы а), б). По ГОСТу сначала идут буквы,
а цифры служат для детализации, поэтому для двух уровней бери `gostenum`.

## Таблицы

```latex
Способы чтения сравниваются в~\tabref{reading}.

\suaitable[reading]{Способы чтения из потока}
Способ               | Что читает     | Где останавливается
\texttt{in >> x}     | одно значение  | перед символом, который не входит в запись значения
\texttt{in.get(c)}   | один символ    | после этого символа
```

`\suaitable[метка]{Название}`:

- Ячейки разделяются чертой `|`, **первая строка — шапка**.
- Метка не обязательна. С ней на таблицу ссылается `\tabref{метка}`,
  полное имя метки — `tab:метка`.
- Название печатается над таблицей слева: «Таблица 1 — Способы чтения
  из потока».
- Первый столбец выравнивается влево, остальные и шапка — по центру.
- Число столбцов берётся по самой длинной строке, недостающие ячейки
  остаются пустыми. Пустая ячейка в середине: `а | | в`.
- Таблица длиннее страницы продолжается на следующей под строкой
  «Продолжение таблицы 1», шапка повторяется.

### Ширина столбцов

Ширины подбираются по тексту, задавать их не нужно. Таблица всегда
занимает всю ширину полосы. Сначала она пробует уместить каждую ячейку
в одну строку, потом — не разрывая слов, потом — разрывая формулы и имена
вроде `Журнал!$A$2:$A$8` или `БД_Продажи` после знаков, и только
в последнюю очередь переносит слова по слогам. Узкий столбец с числом
или датой не сжимается уже самого числа. Писать `\allowbreak` в ячейках
не нужно.

### Особые знаки в ячейках

| Нужно | Как писать |
| --- | --- |
| черта внутри формулы | как есть: `$\|x\|$ \| модуль` — две ячейки |
| черта в тексте ячейки | `\textbar` |
| знаки `& % # _` | `\&`, `\%`, `\#`, `\_` |
| разрыв строки в ячейке | `\newline` |

Для объединённых ячеек и своих ширин таблица набирается обычным
`tabularx` — см. [настройку под методичку](customization.md#таблицы-вручную).

## Рисунки

```latex
Схема алгоритма показана на~\figref{scheme}.

\suaiimg{scheme}{Схема алгоритма программы}
```

`\suaiimg[ширина]{файл}{Подпись}[метка]`:

- Файл ищется в папке `images/` и рядом с `main.tex`. Расширение можно
  не писать. Подходят PNG, JPG и PDF.
- Ширина по умолчанию — `0.8\textwidth`. Рисунок шире полосы урезается
  до полосы, выше трёх четвертей высоты страницы — уменьшается
  с сохранением пропорций.
- Подпись печатается под рисунком по центру: «Рисунок 1 — Схема алгоритма
  программы». Точка в конце подписи не ставится.
- Метка получается из имени файла: `images/scheme.png` → `fig:scheme`,
  ссылка — `\figref{scheme}`. Если один файл вставляется дважды или нужно
  другое имя, метка задаётся целиком в конце команды.
- Рисунок стоит в том месте текста, где написана команда.

```latex
\suaiimg[0.5\textwidth]{scheme}{Схема алгоритма программы}

\suaiimg[6cm]{run}{Повторный запуск}[fig:run-again]
```

## Формулы

```latex
Среднее арифметическое вычисляется по~\formref{mean}:
\suaieq[mean]{\bar{x} = \frac{1}{n} \sum_{i=1}^{n} x_i}
\bar{x} | среднее арифметическое
n | количество чисел
x_i | число с номером $i$
```

<p align="center">
  <img src="images/text.png" width="55%" alt="Страница демо-отчёта с таблицей и формулами">
</p>

`\suaieq[метка]{формула}`:

- Формула печатается отдельной строкой по центру, номер в круглых скобках —
  справа.
- Метка не обязательна. Ссылка — `\formref{метка}`, полное имя метки —
  `eq:метка`.
- Строки `обозначение | смысл` под командой дают пояснения: «где x̄ — среднее
  арифметическое;». Слово «где», тире, «;» и «.» ставятся сами.
- Обозначение набирается как формула, знаки `$` вокруг него не нужны.
  Обозначение с чертой пишется в `$…$`: `$|x|$ | модуль числа`.
- Без строк под командой получается формула без пояснений.

Формула в строке текста пишется как обычно: `$n$`. Многострочные формулы
набираются окружениями `amsmath`; метка с префиксом `eq:` работает
с `\formref` так же:

```latex
\begin{align}
  a &= b + c \label{eq:first} \\
  d &= e
\end{align}

По~\formref{first} получаем…
```

## Листинги

У `\suaicode` две формы: код в тексте и код из файла.

### Код в тексте

```latex
Команды сборки приведены в~\lstref{build}.

\suaicode[bash, build]{Сборка и запуск программы}
    # сборка с предупреждениями компилятора
    g++ -std=c++17 -Wall -Wextra -o stats stats.cpp

    ./stats data.txt

Следующий абзац — с начала строки.
```

`\suaicode[язык, метка]{Подпись}`:

- Код — строки **с отступом** под командой, пробелами или табуляцией.
  Общий отступ срезается, остальной сохраняется.
- Пустые строки внутри кода допустимы. Код кончается на первой непустой
  строке без отступа.
- Внутри кода ничего экранировать не нужно: `%`, `\`, `$`, `{` печатаются
  как есть.
- На строке с командой после подписи может стоять только комментарий.

### Код из файла

```latex
\suaicode[C++]{stats.cpp}{Исходный текст программы}
```

`\suaicode[язык, метка]{файл}{Подпись}[метка]`:

- Файл ищется по указанному пути, а затем в папке `code/`.
- Метка получается из имени файла: `code/stats.cpp` → `lst:stats`, ссылка —
  `\lstref{stats}`. Другую метку задаёт второе слово в квадратных скобках
  (`[C++, full]` → `lst:full`) или полное имя в конце команды
  (`[lst:full]`).

### Параметры в квадратных скобках

| Запись | Что значит |
| --- | --- |
| первое слово | язык |
| второе слово | метка, префикс `lst:` добавляется сам |
| `ключ=значение` | любой ключ пакета `listings` |

Оба слова не обязательны: `\suaicode{Подпись}` даёт листинг без подсветки
и без метки. Метка без языка задаётся ключом:

```latex
\suaicode[label=lst:input]{Входной файл}
    12.5 7 3.25
    -4 10

\suaicode[Python, numbers=none]{Без номеров строк}
    print("привет")
```

Ключи `firstline`, `lastline` и `linerange` в `\suaicode` не действуют.
Часть файла выводит команда `\lstinputlisting` пакета `listings`:
оформление и ссылки у неё те же.

```latex
\lstinputlisting[language=C++, caption={Функция чтения чисел из файла},
  label=lst:read, firstline=18, lastline=39, firstnumber=18]{code/stats.cpp}
```

### Языки

Язык — любой из пакета `listings` (Python, C, C++, C#, Java, Go, SQL, bash,
HTML, …) или один из добавленных шаблоном:

| Язык | Короткие имена |
| --- | --- |
| C++ | `cpp` |
| C# | `cs`, `csharp` |
| Python | `py` |
| bash | `sh` |
| JavaScript | `js` |
| TypeScript | `ts` |
| Kotlin | `kt` |
| Rust | `rs` |
| YAML | `yml` |
| Dockerfile | `docker` |
| JSON | — |

Регистр не важен: `python` и `Python` — одно и то же. Если язык неизвестен,
сборка не останавливается: код набирается без подсветки, а в журнале
остаётся предупреждение `Язык листинга '…' неизвестен`.

### Как выглядит листинг

<p align="center">
  <img src="images/listing.png" width="55%" alt="Приложение с листингом">
</p>

- Подпись над кодом слева: «Листинг 1 — Сборка и запуск программы».
- Рамка от поля до поля, слева номера строк, шрифт Liberation Mono 12 pt.
- Полужирного и цвета нет, комментарии набраны курсивом. Цветной вариант
  и полужирные ключевые слова включаются в
  [настройке под методичку](customization.md#листинги).
- Длинная строка кода переносится со значком ↪.
- Русские буквы в коде и комментариях набираются без настроек.
- Листинг длиннее страницы продолжается на следующей под строкой
  «Продолжение листинга 1», как таблица.
- Подпись внизу страницы без кода не остаётся: если под ней нет места
  на три строки, листинг уходит на следующую страницу целиком.

Окружение `lstlisting` и команда `\lstinputlisting` из `listings` оформляются
так же. Окружение `code` из прежних версий шаблона работает по-старому.

## Ссылки на рисунки, таблицы, формулы и листинги

На каждый рисунок, таблицу, формулу и листинг в тексте должна быть ссылка.
Команды ссылок печатают слово вместе с номером:

| Команда | Что печатает | Метка объекта |
| --- | --- | --- |
| `\figref{scheme}` | рисунке 1 | `fig:scheme` |
| `\tabref{reading}` | таблице 2 | `tab:reading` |
| `\lstref{build}` | листинге 3 | `lst:build` |
| `\formref{mean}` | формуле (4) | `eq:mean` |

```latex
Схема показана на~\figref{scheme}, результаты приведены в~\tabref{errors}.
Среднее вычисляется по~\formref{mean}.
```

- Префикс метки писать не нужно: `\figref{scheme}` найдёт `fig:scheme`.
  Полное имя тоже подходит.
- Слово стоит в предложном падеже. Для другого падежа есть обычный `\ref`:
  `рисунок~\ref{fig:scheme}`, `таблицы~\ref{tab:errors}`.
- `~` перед ссылкой не даёт предлогу остаться в конце строки.
- В приложениях номера получают букву: «рисунке А.1».
- Номер страницы объекта даёт `\pageref{fig:scheme}`.

В VS Code внутри `\figref{…}` и остальных ссылок подсказываются метки
из последней сборки.

## Список источников

```latex
Потоки ввода-вывода описаны в~[1].

\suaisources
Страуструп Б. Язык программирования C++. Специальное издание. М.: Бином, 2011. 1136 с.
Input/output library [Электронный ресурс]. URL: https://en.cppreference.com/w/cpp/io (дата обращения: 12.09.2026).
```

`\suaisources` печатает заголовок «СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ»
с новой страницы и нумерованный список: один источник — одна строка.
Пунктуация в строках не меняется. Ссылки в тексте при этом пишутся
вручную: `[1]`.

Чтобы номера ссылок расставлялись сами, источники ведутся в файле `.bib`,
а под `\suaisources` строк не пишется — см.
[biblatex](customization.md#источники-через-biblatex).

## Приложения

```latex
\suaiapp{Исходный текст программы}

Исходный текст программы приведён в~\lstref{stats}.

\suaicode[C++]{stats.cpp}{Исходный текст программы}

\suaiapp[справочное]{Протокол проверки программы}
```

`\suaiapp[статус]{Название}`:

- Приложение начинается с новой страницы строками «ПРИЛОЖЕНИЕ А»,
  «(обязательное)» и названием по центру.
- Статус по умолчанию — «обязательное»; другой задаётся в квадратных
  скобках: `[справочное]`, `[рекомендуемое]`.
- Приложения обозначаются буквами А, Б, В, … без Ё, З, Й, О, Ч, Ъ, Ы, Ь.
- Рисунки, таблицы, формулы и листинги в каждом приложении нумеруются
  заново с его буквой: «Листинг А.1», «Таблица Б.1», формула «(А.1)».
  Команды ссылок работают как в основной части.
- В содержании приложение записано строкой «ПРИЛОЖЕНИЕ А (обязательное)
  Название».

В тексте на приложение ссылаются словами: `в~приложении~А`.

## Длинные слова и переносы

Строка может перерваться внутри длинного «слова» без пробелов:

- в обычном тексте — после знаков `_ / = + ! -`: `БД_Продажи`,
  `Журнал!$A$2`;
- в `\texttt{…}` — ещё и после `. , ; : ? &` и перед открывающей скобкой:
  `center.yandex.cloud`, `UPPER(TRIM(…))`.

Такой разрыв берётся, только если иначе строка вылезет на поле. Перед
цифрой разрыва нет: `1,5` и `01.01.2025` остаются целыми. Адреса в `\url{…}`
переносятся в любом месте.
